# JARVIS OS — Boot Architecture Specification

## 1. Overview & Boot Modes

JARVIS OS natively implements dual boot paths on x86_64 architectures:
1. **Multiboot 1 / BIOS (Legacy / Direct Kernel Boot)**
2. **Native UEFI (PE32+ EFI Application)**

---

## 2. Boot Protocols & Loaders

### A. Multiboot 1 (Legacy BIOS / QEMU Direct Kernel)
* **Specification**: Multiboot Specification version 0.6.96 (Multiboot 1).
* **Magic Number**: `0x1BADB002` (Defined in `Kernel/Prekernel/multiboot.S`).
* **Flags**: `MULTIBOOT_PAGE_ALIGN (0x1) | MULTIBOOT_MEMORY_INFO (0x2) | MULTIBOOT_VIDEO_MODE (0x4)`.
* **Requested Video Mode**: `1280x1024x32` linear framebuffer.
* **Prekernel Entry Point**: `Kernel/Prekernel/boot.S` -> `_entry` -> `Kernel/Prekernel/init.cpp` -> `init()`.
* **Transition**: Prekernel initializes identity paging (`boot_pml4t`), switches CPU from 32-bit Protected Mode into 64-bit Long Mode with paging enabled, maps physical memory pool, and jumps to 64-bit kernel entry point `Kernel::init()`.

### B. Native UEFI (Modern Bare-Metal PC / Firmware Boot)
* **Specification**: Unified Extensible Firmware Interface (UEFI 2.x+).
* **Artifact**: `Kernel/EFIPrekernel/Kernel.efi` (`BOOTX64.EFI`).
* **Format**: PE32+ (Portable Executable 64-bit) generated by `Lagom::PrekernelPEImageGenerator`.
* **Entry Point**: `Kernel/EFIPrekernel/init.cpp` -> `efi_main()`.
* **Firmware Handshake**:
  1. Queries `EFI_GRAPHICS_OUTPUT_PROTOCOL` (GOP) for linear framebuffer.
  2. Queries `EFI_LOADED_IMAGE_PROTOCOL` and `EFI_SIMPLE_FILE_SYSTEM_PROTOCOL`.
  3. Allocates physical memory maps using `GetMemoryMap()`.
  4. Sets up 4-level PML4 paging tables mapping the 64-bit kernel ELF image.
  5. Exits UEFI Boot Services via `ExitBootServices()`.
  6. Passes boot metadata structure and jumps directly to `Kernel::init()`.

---

## 3. Kernel Entry Point & Execution Pipeline

1. **`Kernel/Arch/init.cpp` (`Kernel::init`)**:
   * Initializes CPU 0 GDT, IDT, and TSS (`DescriptorTable.h`).
   * Sets up interrupt vector handling (`InterruptManagement.cpp`).
   * Configures Physical & Virtual Memory Managers (`MemoryManager.cpp`).
   * Initializes Preemptive Task Scheduler (`Scheduler.cpp`).
   * Mounts root virtual filesystem (`VFSRootContext`) from the Ext2 partition.
   * Spawns PID 1 (`/init` -> `SystemServer`).

2. **`SystemServer` (Userspace Boot)**:
   * Mounts `/proc`, `/sys`, `/tmp`, `/dev/pts`.
   * Activates core daemons: `WindowServer`, `LookupServer`, `NetworkServer`.
   * Activates JARVIS native daemons: `JarvisService` (`/bin/JarvisService`), `JournalService` (`/bin/JournalService`).
   * Spawns `LoginServer` which starts the graphical desktop session and HUD (`JarvisAssistant`).

## 4. Storage & Image Formats

| Component | Format | Tooling |
| :--- | :--- | :--- |
| **Partition Table** | GPT (GUID Partition Table) / MBR | `parted`, `gdisk`, `fdisk` |
| **EFI System Partition (ESP)** | FAT32 (type `EF00` / `c`) | `mkfs.vfat -F 32` / `mformat` |
| **Root Filesystem** | Ext2 (Extended 2 Filesystem) | `mke2fs` / `genext2fs` |
| **Kernel Binary (Multiboot)** | `elf32-i386` | `objcopy` + `Prekernel` |
| **Kernel Binary (UEFI)** | PE32+ (x86-64 EFI executable) | `PrekernelPEImageGenerator` |

## 5. QEMU Launch Configuration

JARVIS OS is executed in QEMU with the following validated hardware machine configuration:
```bash
qemu-system-x86_64 \
    -kernel Kernel/Kernel \
    -append "root=nvme0:1:0 hello" \
    -m 2G \
    -smp 2 \
    -cpu max,migratable=no,-x2apic \
    -device virtio-gpu-pci \
    -device nvme,serial=deadbeef,drive=boot-drive,logical_block_size=4096,physical_block_size=4096 \
    -drive file=_disk_image,if=none,format=raw,id=boot-drive \
    -device ich9-intel-hda -device hda-output,audiodev=snd0 \
    -audiodev coreaudio,id=snd0 \
    -device e1000,netdev=breh \
    -netdev user,id=breh,hostfwd=tcp:127.0.0.1:18888-10.0.2.15:8888,hostfwd=tcp:127.0.0.1:18000-10.0.2.15:8000 \
    -display cocoa,gl=off
```
